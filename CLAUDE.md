# Notes for Claude

This repo is a personal Rust tutor app and its lessons. Read these first:

1. `PROGRESS.md`: who the learner is and where they are. Teach from there.
   Its "Learner profile" block is generated by the app; never edit it by hand.
2. `ROADMAP.md`: lesson order and app milestones.
3. `docs/SHARED-FORMAT.md`: lesson and history formats. **They are shared with
   the `learn-nodejs` repo; change them in both repos or not at all.**

Core requirement (from the learner): **lessons must adapt to the person's
learning, style, progress and reviews.** Nothing is one-size-fits-all:
- What comes next is chosen from the history (`docs/SHARED-FORMAT.md`,
  section 5): reviews when due, extra drills after a struggle, harder stretch
  exercises after an easy win, otherwise the next core lesson.
- Reviews use a *fresh* exercise on the same concepts (a drill), not a replay
  of code already written.
- The learner rates each solved exercise (too easy / about right / too hard);
  respect that signal together with runs-to-solve and recurring mistakes.
- When adding content, add drills and stretches for each core lesson, not just
  the next core lesson. The in-app tutor also generates targeted drills
  (`lessons/NNg-*`, `generated: true`); its prompts are in `docs/tutor/`,
  shared with the other repo.

Lesson design (from the learner's feedback: lessons must teach, not just test):
- Learn first, then do: every exercise has *Learn the idea* (with a runnable
  ```run example), a *Quick check* (```predict), then *Your turn*, an
  *Example*, three graded *Hints* and a *Review* tip. Format:
  `docs/SHARED-FORMAT.md`, section 1.
- One practical skill per exercise, about 8 minutes, set in the
  device-and-service story; test names are plain sentences.
- Every ```predict answer must be exactly what the code prints; check it.
- Every core lesson has a ```visual: an animated step-through of what the code
  does at runtime, with at least one "What if it goes wrong" scenario. Give
  scenarios a `check` (output or error code); the tests run it for real.

Teaching rules:
- The learner is a professional Java developer. Contrast with Java; skip
  basics Java already covers. Spend time on ownership and borrowing.
- Sessions are ~20 minutes: one or two exercises of ~8–12 minutes each.
- Never hand over a full solution unprompted; give the smallest hint that unblocks.
  When explaining a compiler error, start from its error code.
- App: `app/` (std-only web server; keep it dependency-free unless there's a
  strong reason). `app/public/` is shared byte-for-byte with `learn-nodejs`.
  Check with `cargo test` at the root, then `cargo run` and try a lesson.
- Each lesson is a crate in the workspace (`lessons/NN-slug/`), with tests in
  `src/lib.rs`. Tests must pass against a reference solution before committing
  (do not commit the solution).
